# api-collector

Асинхронный опрашиватель публичных JSON-API. Читает конфиг со списком источников,
опрашивает их параллельно, переживает отказы, приводит ответы к собственным
типизированным моделям и потоково пишет результат в файл. На выходе — данные
и отчёт: что получилось, что не получилось и почему.

## Возможности

- **Параллельный опрос источников** — результаты собираются по мере готовности
- **Ограничение параллельности** — не больше 15 одновременных запросов
- **Retry с экспоненциальной задержкой** — повторяются только временные сбои
- **Таймауты** — на каждый запрос (из конфига) и общий на обработку источника (12 c)
- **Устойчивость к отказам** — отказ одного источника не роняет остальные,
  упавшие попадают в отчёт как записи с ошибкой
- **Потоковая запись** — собранное не копится в памяти, каждая строка файла пишется сразу
- **Типизированные модели** — ответ каждого источника разбирается в свой `frozen` dataclass
- **Своя иерархия исключений** — никаких голых `except:`, ошибки не теряются молча

## Установка

Требуется **Python ≥ 3.14**.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .                 # сам пакет
pip install -e ".[dev]"          # + инструменты разработки (mypy, ruff, pytest)
```

Пакет ставится в режиме разработки и запускается из любой директории.

## Использование

```bash
api-collector config.toml                    # результат → ./results.jsonl
api-collector config.toml -o report.jsonl    # свой файл результата
api-collector config.toml -v                 # подробное логирование (DEBUG)
```

### CLI

```
usage: api-collector [-h] [-o OUTPUT] [-v] config_path
```

| Аргумент | Описание |
| --- | --- |
| `config_path` | путь к файлу конфигурации (позиционный) |
| `-o, --output` | путь к файлу результата; по умолчанию — `results.jsonl` в корне проекта |
| `-v, --verbose` | подробное логирование (уровень DEBUG) |

Коды выхода: `0` — успех, `1` — ошибка конфига или выполнения, `130` — прерывание
пользователем (`Ctrl+C`).

## Конфигурация

Конфиг — TOML-файл с таблицами `[[API]]`. Поля:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `name` | да | Имя источника; должно совпадать с именем известного парсера (ниже), иначе конфиг отклоняется |
| `URL` | да | Адрес публичного JSON-API |
| `timeout` | нет (по умолчанию `5`) | Таймаут запроса в секундах, должен быть > 0 |

Пример (`config.toml` в корне проекта):

```toml
[[API]]
name = 'JokeApi'
URL = "https://v2.jokeapi.dev/joke/Any"
timeout = 5

[[API]]
name = "OpenMeteo"
URL = "https://api.open-meteo.com/v1/forecast?latitude=55.752&longitude=37.6178&current=temperature_2m&timezone=auto"
timeout = 5

[[API]]
name = "Exchangerate"
URL = "https://open.er-api.com/v6/latest/USD"
timeout = 5
```

### Встроенные источники

Пять источников с разными форматами ответов, у каждого своя модель и свой парсер:

| `name` | Модель | Формат ответа |
| --- | --- | --- |
| `JokeApi` | `JokeApi` | плоский объект, возможны два варианта шутки (`joke` / `setup`+`delivery`) |
| `Noozra` | `Noozra` | список статей в поле `articles`, даты в разных форматах |
| `BoredApi` | `BoredApi` | плоский объект «идеи, чем заняться» |
| `OpenMeteo` | `OpenMeteo` | часть данных вложена в объект `current`, требуется «расплющивание» |
| `Exchangerate` | `Exchangerate` | поле `rates` — словарь курсов валют |

## Формат результата

Файл результата — JSONL: одна строка — один источник. Результат пишется сразу
по готовности, поэтому порядок строк не обязан совпадать с порядком в конфиге.

Успех:

```json
{"name": "OpenMeteo", "data": [{"latitude": 55.75, "longitude": 37.625, "timezone": "Europe/Moscow", "timezone_abbreviation": "GMT+3", "time": "2026-09-09 18:30:00", "temperature_2m": 19.0}]}
```

Отказ (источник не достали или ответ не разобрался — остальные источники живут дальше):

```json
{"name": "Noozra", "status_code": null, "errors": ["Unable to connect to 'https://noozra.com/api/articles?category=tech&limit=2'", "All connection attempts failed"], "raw": null}
```

`raw` и `status_code` заполняются, когда упал HTTP или тело ответа неожиданно
не является JSON, — так что даже отказ можно разобрать.

## Как это работает

### Конвейер

```
config.toml → read_config() → Source[]
                        ↓
              asyncio.as_completed(...)   ← опрос идёт параллельно
                        ↓
             processing_source()          ← общий таймаут (12 c)
                        ↓
        CollectorClient.fetch_source()    ← семафор + retry
                        ↓
          parsers.parse_source()          ← ответ → своя dataclass-модель
                        ↓
       write_result() → потоковая запись в JSONL + печать в терминал
```

### Асинхронность

- `httpx.AsyncClient` живёт внутри асинхронного контекстного менеджера —
  соединения закрываются, даже если внутри что-то упало (`__aexit__` вызывает `aclose()`)
- `asyncio.Semaphore(15)` ограничивает число одновременных запросов
- Общий лимит на обработку одного источника — `asyncio.timeout(12.0)` вокруг запроса
- `asyncio.as_completed` отдаёт результаты по мере завершения, не дожидаясь
  самого медленного источника

### Retry

Декоратор `@retry()` на `get_request()`:

- повторы с экспоненциальной задержкой: `1с → 2с → 4с → …`
- по умолчанию `max_attempts=2`, `initial_delay=1с`
- повторяются только таймауты, ошибки соединения и HTTP-ошибки из
  `RETRY_CODES = 429, 500, 502, 503, 504` (временные сбои)
- `400/401/403/404/…` и ошибки разбора **не** повторяются
- `KeyboardInterrupt`/`SystemExit` сквозь декоратор не трогаются

### Иерархия исключений

```
CollectorError
├── NetworkError
│   ├── NetworkTimeoutError      # таймаут запроса
│   ├── NetworkConnectionError   # не смогли подключиться
│   ├── NetworkHttpError         # HTTP-статус не 2xx
│   │   └── RetryHttpError       # переповторяемый код (429/5xx)
│   └── RequestError             # HTTP 200, но тело не подошло
└── ConfigError
    ├── ConfigDecodeError        # TOML не разобрался
    ├── ConfigIncorrect          # неверная структура / неизвестный source
    ├── ConfigFileError
    │   ├── ConfigNotFound
    │   └── ConfigPermissionError
    └── InvalidUserPath          # путь не ведёт к файлу
```

Прикладные ошибки (HTTP 200 с ошибкой в теле, например `error: true` у JokeApi)
перехватываются парсером и превращаются в `SourceFailure`, а не в исключение.

### Логирование

- По умолчанию уровень `INFO`, с `-v` — `DEBUG`
- Служебный вывод идёт через `logging`, а не `print`: при параллельном опросе
  строки вывода не перемешиваются
- Файл результата отделён от служебного вывода в терминал
- Цвета уровней — только если лог идёт в терминал

## Структура проекта

```
api_collector/
├── __init__.py
├── main.py            # CLI, оркестрация, потоковая запись, контроль таймаутов
├── config.py          # чтение и валидация TOML-конфига
├── models.py          # frozen dataclass'ы: Source, результаты и модели источников
├── client.py          # retry-декоратор, CollectorClient, get_request
├── parsers.py         # разбор ответа каждого источника в свою модель
├── exceptions.py      # иерархия исключений проекта
└── logging_config.py  # настройка логирования (цвета, уровни)
```

Слои разделены: конфиг → модели → клиент → парсеры → точка входа.
Никакие «сырые» словари не покидают место разбора.

## Разработка

```bash
python -m pytest                              # тесты (63 шт., включая асинхронные)
python -m mypy --strict api_collector tests   # строгая проверка типов
ruff check .                                  # линтер
```

- `mypy --strict` без единого `# type: ignore` — обязательное правило проекта
- Тесты покрывают retry-декоратор, HTTP-клиент, конфиг, парсеры и оркестрацию;
  retry тестируется моками сбоя сети — без реальной сети
